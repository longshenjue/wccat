# 长期资料库实现与审查记录

设计：`docs/superpowers/specs/2026-11-18-evidence-library-design.md`，2026-11-18 用户确认实施。

范围：在原 SQLite 中增加独立保留的证据、内容版本、指标、搜索、事件与分析引用；接入现有采集与话题分析；提供显式历史回填、完整备份和只读验证。现有评分与六表归档格式保持兼容。新供应商 HTTP adapter、周期研究任务与公共查询 API 不属于本阶段。

## 审查及修正

一次独立的整体验证审查初评为尚不能交付，发现下列实质问题。随后在同一修正批次补充失败用例、修正实现并运行全量回归；没有用第二次审查代替回归验证。

| 问题 | 修正与回归 |
| --- | --- |
| 签名 URL、camelCase secret、旧业务表仍可能保存凭据 | URL 与嵌套对象脱敏；自动快照、日报、分享、分析与日志写入同步处理；备份读取检查新增凭据标记不残留 |
| 大整数 ID 精度及共享 URL 合并错误 | 实际归一化也保留精确整数文本；已知不同平台 ID 冲突时回滚，不静默合并 |
| 同名内容匹配了错误原始对象 | 优先 URL/ID；标题仅在唯一匹配时使用，否则明确保留 normalized_only |
| 历史回填复制新采集、结论及尝试 | 复用 live run、稳定快照 run、结论输出和 legacy log ID；普通与 force 回填均做回归 |
| 结论替代错误对象、输入被同小时刷新替换、开发入口未保存 trace | 只替代前次结论；保存原话题与 run ID；明确 attempt 引用并保留实际模型输入 |
| HTTP 200 的拒绝和无效 JSONP 被当成空结果 | 平台业务失败与解析失败保留 failed 状态，真实空列表仍为 empty |
| 搜索重试返回文档列表变化、命中数为零 | 从已存命中恢复稳定次序，保存真实 item_count |
| 缺表备份仍可能通过校验 | 备份发布及 verify 均检查必需业务表、证据表和 schema 版本 |
| 截断后仍声称完整，字节含义混淆 | partial 状态，上游/捕获/压缩字节分开，未知上游长度不推断 |
| 恢复文档的文件名可能导致空库 | 提升为实质运维风险并修正文档：先验证备份，再复制到新目录并命名 wccat.sqlite |

补充验证：历史 prompt/算法版本未知时不填当前值；新结论继承明确尝试的 prompt hash。原分享测试中通用单词 `test`/`fixture` 同时充当假 Key 与正文/模型名，改为独立假凭据；原有图片、编辑、归档断言保留，新增真实运行时 Key 被回显时仍脱敏的检查。

## 实施裁定（Rulings I made）

1. 每次真实刷新是一次新观测；只有同一 run 的重试幂等。若误判为新请求，调用方会重复保存观测，因此 adapter 必须复用本次请求 ID。
2. 新搜索/评论网络 adapter、供应商权限、周期 AI 与公共收费 API 留待实际 Key 和后续范围。当前只交付仓储契约；代价是新供应商数据尚不会自动入库。
3. 不自动扫描或重写历史记录中的潜在凭据。完整备份原样保留旧记录；代价是旧凭据若已存在，备份仍含有，必须私密保存并另行处理。
4. CLI 使用 `node --import tsx`，避免当前沙箱中 tsx launcher 的本地 IPC 权限失败；依赖和实际 TypeScript 执行入口不变。
5. 生产构建在独立工作区使用本地依赖副本；Turbopack 拒绝指向另一仓库根的 node_modules 软链接。未增加依赖，代价仅是本机额外磁盘占用。

未延期处理审查中的实质问题。恢复文件名原被列为轻微问题，因可能误启动空库而提升后修复。
