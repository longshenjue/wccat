# 管理员数据归档与空间清理设计

状态：用户已于2026-11-13确认按本设计继续实现；验证只使用隔离临时数据，不执行真实数据删除。

## 需求与选择

用户已明确：不接外部存储；下载并清理后的旧小时历史可以从当前站点移除；操作时间不固定，允许积累三个月后仅处理第一个月。用户提出长期保留日报、删除小时记录以节省空间。

已确认方案：长期保留所有已生成日报，由管理员按月份或日期范围按需清理旧小时记录，不默认设置自动过期或强制每月下载。单管理员登录、48小时保护、归档格式和恢复方式按本设计实施。

考虑的路径：

1. 全部历史留在当前卷：查询简单，但持续增长，不符合节省小容量卷的目的。
2. 外部存储承载旧历史：当前站仍可查全部历史，但用户已排除外部存储。
3. 保留日报，小时历史可下载后移除，或明确放弃后直接清理：推荐；不固定删除时间，归档可以在其他部署恢复查询。

## 已确认的代码事实

- 当前业务数据写入 `/app/data/wccat.sqlite`，使用 WAL。`daily_reports` 没有引用 `snapshots` 的外键。
- 日报 payload 内嵌 Top 10、已生成的逐话题分析、稿件、来源地址和英文分享内容；日报展示、中文/英文 PNG 不依赖重新查询小时库。
- 删除小时数据不能补齐尚未生成的日报、AI 分析或英文翻译。日报没有保留当日全部热点，也不能用于重新计算原来小时榜。
- 封面只保存 URL，外部图片将来失效不在数据归档可保证的范围内。
- 目前只读一个主库，没有月归档发现机制；生产 `/admin` 与旧数据库 CRUD API 关闭，不能直接移除这项保护来上线管理员功能。
- Web 与 worker 是不同进程，共用同一个 SQLite。数据库管理必须协调所有进程写入。

## 用户可见行为

### 管理员入口

- 提供专用的数据管理登录页和后台，不重新开放任意表 CRUD。
- 管理员密码由运行时环境配置，保存密码散列；提供本机生成散列的维护命令，不把明文密码或会话密钥写入仓库。
- 建议环境变量：`WCCAT_ADMIN_PASSWORD_HASH`、`WCCAT_ADMIN_SESSION_SECRET`。未配置时后台默认不可用。
- 登录后查看主数据库、归档文件、临时导出占用与持久卷剩余空间，按月份列出小时快照数、日报数、AI 记录数与大致体积。
- 支持选择一个月、多个月或起止日期；以北京时间为准，结束日期按当天全部时间包含。
- 列表不限制为最近 12 天；日报页增加月份/日期导航，以便长期保存的日报确实可被访问。

### 三种独立操作

1. **仅下载**：选择“日报归档”或“完整归档”，生成、校验、下载，不改变原数据。
2. **下载后清理小时数据**：完整归档下载并经管理员确认已保存/校验后，自动完成该次确认范围的小时清理与空间回收，保留全部日报。
3. **仅保留日报，清理小时数据**：无需强制下载；预览删除数量与缺失日报日期，明确确认放弃相应小时历史后执行。这个选择不会创建归档，也不能事后从日报恢复全部小时数据。

默认不勾选删除选项。点击下载、服务器发完响应都不等于文件已安全存到用户设备；不使用这两种事件直接触发删除。清理确认绑定导出任务、时间范围和数据版本，不能被替换为任意日期。

后台的步骤为：选择范围 → 查看预览 → 下载（如选择）→ 确认清理 → 查看保留数量、删除数量、实际回收空间。取消、导出失败、下载中断时不触发清理。清理失败必须显示已执行到哪一步，不能统一显示成功。

## 时间范围与保留规则

- 不设置按周/月到期自动删除，也不要求月末必须处理。
- 初始只提供管理员主动操作；之后可增加自动策略，但不作为本次上线内容。
- 只清理本次选中的主库小时记录；不清理任何 `daily_reports`，包括中文、英文、已生成的 AI 详情和稿件。
- 保留最近 48 小时，按真实 `generatedAt` 判断，并保护最新小时记录，避免影响当前榜单、前后小时比较和过去 24 小时日报生成。预览显示实际可处理范围。
- 对旧小时记录，删除范围包括 `snapshots`、关联的 `raw_items`、`topics`、`topic_analyses`，以及按 snapshot_date 关联的 `ai_analysis_logs`。
- 预览必须明确：保留的是“已经生成的日报”；显示范围内未生成日报的日期。缺失日报日期的推断需考虑 00:10 日报通常覆盖前一天的小时记录，不能简单把同日没有日报视为完全没有覆盖。
- 缺失日报不自动调用 AI 补生成；管理员可先通过现有受控命令补齐，或在明确确认中选择放弃那些小时记录。
- 清理后历史小时页应明确提示该日期已清理；不能默默显示最新榜单冒充该日期。

## 归档内容与恢复

归档以月份组织；跨月日期范围拆成对应月份的包。允许月份中间导出，文件携带实际范围和唯一标识，因此以后可以继续处理该月剩余数据。

建议下载格式为 `wccat-YYYY-MM-<range>-<id>.sqlite.gz`：

- 解压后为独立 SQLite 文件，使用受控、版本化的业务 schema。
- 日报归档只包含选择范围内 `daily_reports` 和归档元信息。
- 完整归档包含选中小时、关联来源、聚合话题、分析、日志，以及选择日期范围内的日报。日报已内嵌的跨月分析保留在 payload 中。
- 元信息包含格式版本、schema 版本、北京时间范围、导出时间、各表数量、内容校验信息和归档 ID。
- 下载页面提供整个下载文件的 SHA-256，内部另校验表/记录完整性。归档不包含账户密码、环境变量和 API Key。
- 用一致性读取构造导出数据，不直接复制仍在写入的 `.sqlite` 主文件；完成后校验数据库完整性与业务数量，再提供下载。
- 按行迭代写出与压缩，不能把整月数据加载进 Node 内存。后台生成任务有进度，避免长请求超时。
- 临时导出放在 `/app/data/admin-exports`，不放到网站 public 或可查询的 archives 目录；同一时间只生成一个包，支持下载重试和取消。过期临时包可以清理，但绝不连带删除源数据。
- 生成前检查临时未压缩数据库、压缩文件、WAL 和后续回收所需的空间；不足时不启动破坏性操作，并提示缩小导出日期范围。

其他部署的使用方式：

```text
/app/data/
├── wccat.sqlite
└── archives/
    ├── wccat-2026-09-....sqlite
    └── wccat-2026-10-....sqlite
```

- 压缩包先由受控 CLI 校验并解压注册到该目录；CLI 支持批量注册多个月份，不要求用户手工合并数据库。
- 程序扫描/重建归档目录索引，之后按日期查询相关文件，跨月和历史日报列表合并结果；不一次 ATTACH 全部月份，避免数据库数量限制。
- 主库持续写入，已注册归档只读。归档数量不应变成进程长期打开文件句柄数量，使用有界连接缓存。
- 内容相同的包重复注册不重复显示。相同业务主键按业务生成时间选择较新版本，时间相同优先主库；主库的中文日报与已补生成英文不被旧归档覆盖。
- 同一小时的原始条目与话题明细应来自选中的同一快照版本，不能混合不同包的数据。自增行 ID 不作为跨部署去重身份。
- 多个文件是否可查由它们是否存在且已通过注册校验决定；当前云端下载后移除的文件不会继续远程可查。
- 本次不接外部对象存储，也不实现自动向另一服务器同步。文件格式和注册命令支持后续迁移。

## 清理一致性与磁盘回收

- 导出和预览不修改业务数据；不能通过执行预览触发升级、清理或归档迁移。
- 导出记录本次业务数据的版本摘要。下载后清理之前重新核对，若期间有补充分析/翻译等变化，不删除未包含在归档的新数据，应拒绝旧任务并要求重新预览/导出。
- 直接清理同样绑定预览版本，使用事务，出现冲突时不部分删掉某些表。
- 引入主库中的维护任务/写入协调机制，所有 web、worker、CLI 写入入口遵守。正常抓取/AI 调用结束后提交前也要检查，不能让在途结果写回已清理的快照。
- 导出使用独立一致性读取连接；不要用主 Web 连接开启长期事务。清理和压缩在受控后台任务中运行，短时间暂停写入，并确保失败后恢复 worker 调度。
- 原有 SQLite 默认不会因 DELETE 立即缩小。后台必须区分“可复用空页”与“实际已归还给卷的空间”。
- 优先为主库建立可逐步回收空间的 incremental auto-vacuum 支持；已有数据库开启时需要一次受控 VACUUM，不在普通网页访问或启动迁移中偷偷执行。
- 初始化/压缩前进行可用空间检查；普通 VACUUM 可能需要额外约两倍原数据库空间，不能等磁盘接近满时仍强行尝试。
- 若空间不足以初始化回收模式，保留原数据，显示可执行的维护步骤；不得报告已释放物理空间。实施时可使用受控维护 CLI，并在导出/清理上线说明中写明首次初始化流程。
- 空间回收采用分批执行与 checkpoint，限制 WAL 增长；执行后重新读取真实文件大小和卷空间。崩溃后依赖事务/任务状态恢复，不能通过裸替换主文件让其他进程继续使用旧连接。

## 安全与范围

- 所有管理页面、统计、下载、任务和清理 API 独立验证管理员会话，不能只隐藏按钮。
- 单管理员、密码散列验证、有限期会话；生产使用 Secure/HttpOnly/SameSite Cookie，修改操作检查来源并防跨站请求；登录尝试有节流。
- 不把管理员配置放入客户端 bundle，不在日志记录密码、会话或 API Key。
- 下载仅接受服务器生成的归档 ID，不接受任意磁盘路径。无登录访问不泄露文件内容或任务信息。
- 归档读取验证格式、schema、范围、大小和完整性；不执行导入文件内的任意 SQL、迁移脚本或扩展。
- 测试使用独立临时数据库，导入前即确定临时路径，并断言实际数据库路径；不对用户现有数据库试删，不对云端执行清理验收。

## 验收标准

1. 未登录无法查看、下载或删除数据；未配置管理员秘密时不可用。
2. 三个月数据可只导出首月；仅下载不改变任何源表。
3. 可以清理首月小时数据，同时该月全部既有日报 payload 保持不变；中英文 PNG 仍可生成。
4. 日报或英文尚不存在时，界面正确提示，不用模板或空文件冒充已备份。
5. 最近 48 小时与最新记录受到保护；删除关联表和日志正确，其他月份不受影响。
6. 下载未确认、任务失败、数据版本改变时不执行归档后清理；直接清理有明确独立确认。
7. 不足空间时保留源数据，真实展示容量限制；具备空间条件时实际文件体积/磁盘占用下降。
8. 模拟 worker 在途写入、维护冲突、重启和失败后重试，不丢失未选择的数据，不静默恢复已删小时。
9. 同一包重复注册、同月多个部分包、多月、跨月 24 小时查询、相同日期的新旧日报都符合去重与优先级规则。
10. 新部署只需原应用、环境配置与已验证归档目录即可浏览其历史；不要求重新抓取或重新调用 AI。

## 实施顺序

这是涉及认证、归档格式、查询与后台维护的一个完整功能，不是重新开放现有管理员 CRUD 的小修改。

建议按同一设计分阶段实施并逐步验证：管理员登录和统计 → 月/日期归档与注册查询 → 保留日报的清理和实际空间回收 → 浏览器验收与部署说明。实现前等待用户确认本设计，再编写实现计划。
