# 管理员按日期生成日报与任务日志

## 目的与范围

管理员在 `/admin` 选择日报日期并生成，不再进入容器 Shell。用户已明确：同日期已有日报时直接重新生成并覆盖。仅实现本功能与对应日志；其他后台增强由用户另行挑选。

## 方案

- **推荐复用现有独立进程任务**：扩展管理员任务类型、登录校验和两秒轮询。页面关闭后继续运行；与现有归档、清理任务共享串行限制，防止同时维护数据库。日志按任务持久化，可在页面恢复后查询。
- 同步页面请求直接生成：代码较少，但生成耗时取决于多次 AI 请求，页面请求易超时，且难以恢复进度，不采用。
- 新增队列服务或外部日志服务：不符合目前单实例、低成本、不接外部存储的约束，不采用。

## 日期与覆盖规则

默认日期为最近一个已结束的北京时间 02:00 窗口对应日期。选择 D 日表示 D-1 日 02:00 至 D 日 02:00，时间边界沿用 `(start, end]`；页面明确显示日期及 UTC+8。

拒绝无效日期、未来或尚未结束的窗口。使用主库与已注册归档中的小时快照；只读归档不被修改，生成结果写入主库。没有有效快照/话题时拒绝生成，保留已有日报；有数据但采集不完整时展示实际采样数量。

按钮明确为“生成 / 重新生成日报”，说明覆盖已有日报且会调用 AI。用户已选择直接覆盖，不再要求额外勾选覆盖开关。接口、实际任务运行前都检查日期与数据，避免校验后数据被清理的竞态。沿用业务写入代际校验。

## 页面与日志

管理员页新增“手动生成日报”区块：日期、统计窗口、已有日报状态、采样数量、执行按钮，以及对应任务的阶段状态、日志、完成后日报链接。

阶段覆盖：准备与读取快照、汇总 Top10、补充 TOP1 分析（或复用）、生成中文稿件、保存中文日报、英文翻译及校验重试、保存英文、结束。显示开始时间、每条日志时间、警告/错误、最终实际模型与英文可用状态。

中文已保存而英文失败时显示“中文已生成，英文未就绪”，保留翻译错误；不会把整次操作标记为完全成功。AI 返回本地回退内容时明确显示模型来源。日志同时输出至容器日志，后台查看无需 Shell。

日志作为文本显示，不执行 HTML。只展示该任务输出，不开放任意 Shell 执行或全站文件读取；隐藏 API Key、登录及会话秘密。每任务日志最多 256 KiB，超限移除最早日志并显示截断提示；任务日志按 30 天与总量 20 MiB 的上限回收，不影响业务日报、归档文件或已有导出凭证。仅登录管理员可以读取。

## 实现约束与验证

沿用当前 Node/SQLite、独立任务子进程、管理员会话与同源 POST 校验，不新增基础设施。不支持批量多日补生成或任务中途强制取消；当前串行任务运行时禁用提交，服务重启导致中断则沿用失败恢复逻辑。

增加日期参数解析与安全校验、权限、无数据不覆盖、同日期覆盖、日志权限和限量、中文成功英文失败、任务结束状态等回归测试；测试使用临时数据库与假 AI 响应。实现后 code review，修复问题并验证，再按用户既有授权 commit/push。

## 确认

用户已批准按此设计实现，暂不添加其他后台功能；实现后先 code review、修复并验证，再 commit/push。
