# 管理员后台分区、历史条目与热度变化

## 需求与边界

本次需求来自同一轮讨论：后台按 Tab 分区；按日期查看小时报 item info 和日报 item；小时报条目提供查看详情、打开原文、复制 JSON、热度变化；放开手动生成日报的未来日期限制。用户明确要求不自动推送，完成后 code review，代码留在本地，只有再次明确要求才 push。

沿用已有管理员登录、视觉样式、主库与注册归档、独立生成任务及日志。查询和图表只读，不重新抓取，不触发 AI。没有编辑/删除条目、AI 重分析或新抓取按钮。

## 信息架构

推荐统一 `/admin` 页面与五个 URL 可恢复的 Tab；另一方案是增加多个独立后台页面，后续导航与共享状态成本更高，当前功能量不需要。

| Tab | 内容 |
| --- | --- |
| 概览 | 现有存储容量、月份摘要、当前任务提示、各功能入口 |
| 小时报 | 日期、当日实际采样时间列表、聚合话题列表、原始平台条目列表、详情与热度变化 |
| 日报 | 日期选择、已有日报与 Top10 条目、已有 AI 分析/稿件/英文、生成与覆盖入口 |
| 归档与存储 | 原有范围预览、导出、确认清理、临时文件及空间回收 |
| 任务日志 | 原有全部后台任务、状态、对应生成日志、下载与结果入口 |

页头保留站点入口、管理员退出和当前任务状态。Tab 切换不终止后台任务，不清空日期、分页及选中条目；URL 保留 tab、日期、快照及条目标识，刷新及浏览器返回可恢复。手机 Tab 横向可滚动，详情采用整宽面板，控件可触达。

## 小时报查询

按快照 ID 所属的北京时间自然日选择，列出当天真实存在的采样时段，同时显示实际保存时间，不虚构每小时都有数据。默认选择当天最新可用采样；没有数据时显示空状态，不回退到其他日期的最新榜单。

提供“聚合话题 / 原始条目”两种列表，按来源与标题关键词筛选，每页 20 条，服务端分页，上限 100。详情展示标题、来源、原始链接、热度分或平台原始热度、排名、采样时间、来源条目、已有 AI 分析及实际模型；原始条目还展示已保存的互动数据。字段未保存时显示缺失状态。

条目操作：查看详情、打开原文、复制该条目 JSON。原始条目关联到明确的聚合话题时可查看其趋势，否则只显示自身信息。链接以安全 http(s) 形式打开，JSON 作为文本复制，不执行其中内容。

## 日报查询

按 reportDate 查询已保存日报；显示统计窗口、生成时间、实际模型、Top10、采样次数、AI 分析及中英文状态。点击日报条目展开详细信息及已有来源链接。中文/英文稿件仅展示已有内容，浏览不补译。

主库和注册归档统一读取，同日/同快照按生成时间选择新版本，时间相同主库优先。先确定胜出版本，再读取其子项和分析；不直接复用跨来源独立择新分析的接口。分页游标与条目定位携带版本标识，版本变化时要求重新读取，不将旧行 ID 用于新版本。已清理且未恢复的数据明确显示不可用。

## 热度变化的分析与展示

分析任务为单话题时间变化，采用上下两张共用时间范围的 SVG 采样折线图，不混用双纵轴：

1. **综合热度分变化**：纵轴为系统 heatScore，不标成浏览量或人数。
2. **榜单排名变化**：纵轴倒置，#1 位于上方。

入口在聚合话题详情中。默认展示所选日期当天，可切换以该日为结束日的近 7 天、近 30 天；全部日期与时间标明 UTC+8。顶部显示观测峰值热度、最佳排名、有效观测次数，避免用采样次数冒充持续小时。

按锚点话题 ID、标准化标题及完整标题共同校验。完整标题校验只规范空格、大小写与标点，不删除停用词或截断，防止现有标准化逻辑的 48 字截断别名及哈希碰撞。空标题、同一采样中多个歧义匹配不连线；不依靠模糊标题或 AI 合并。界面说明按同标题记录追踪，标题变体可能拆分轨迹。原始条目须通过来源、URL 与标题等明确 occurrence 对应关系关联聚合话题。

横轴为快照采样时段，提示中同时给出实际保存时间。该快照存在但没有匹配记录时标记“本次采样未匹配此话题”，避免把标题变化断言为掉榜；这些点打断连线。没有记录的时段不补热度 0 或虚构排名。相邻观测间隔超过 4 小时时用虚线并标出间隔，不据此断言采集失败；不使用全窗口单一中位间隔来推断混合 1h/4h 的缺采样。连线仅辅助阅读相邻观测，不代表中间时段的实际热度。只有一个点时显示单点。

点击/触摸/键盘选择采样点，显示时间、热度分、排名、来源数量，提供“查看这次采样”。同时提供可展开的数据表，重要信息不依赖悬停。蓝色表达热度、粉色表达排名，选中点同时用大小/边框区分，图例与文字说明齐全。

技术约束：仅展开详情时加载一组图；React 独占 SVG，不新增重型图表库。先按归档元数据排除无关范围，每个相关来源一次读取快照元数据并择优，再分组查询胜出来源的单话题标量字段；不逐快照循环调用全来源读取，不加载 30 天全部 payload/rawItems。范围最多 31 天、至多约 744 个小时键，查询参数校验、可取消旧请求、无数据时有明确空态；原始数据表是图形不可用时的替代。

## 放开手动日报日期限制

日期输入移除最大日期；后端仅校验合法 YYYY-MM-DD，不再因未来或尚未到 02:00 而拒绝。

选择 D 日，目标窗口仍为 D-1 日 02:00 → D 日 02:00。允许在窗口结束前，使用截至执行时已采集的有效快照提前生成。比如北京时间 11 月 13 日下午选择 11 月 14 日，会使用 11 月 13 日 02:00 后已有采样；不生成未来新闻，不读取晚于执行时刻的异常未来采样。

预览和生成共享明确的目标 start/end 与执行开始时的 observedUntil，筛选 `(start,min(end,observedUntil)]`。不能把 observedUntil 直接传给会回推 24 小时起点的旧 selectDailySnapshots；执行时间过滤在候选条数限制前生效，避免异常未来记录挤掉有效数据。

结果持久化目标窗口、实际采样范围、采样数与提前生成标记，并在后台及日报页展示。旧日报没有该标记时按原格式展示。没有有效采样仍禁止生成或覆盖；日期放开不等于允许用空内容覆盖。已有日报仍按用户已选规则直接覆盖。

自动任务保持每天北京时间 02:00 的既有规则，手动日期选项与自动调度独立。

## 权限、性能与验证

所有新增查询只对登录管理员开放，生成继续验证同源 POST 与后台串行限制。Tab 页面按需查询，任务状态轻量轮询，趋势查询不启动 worker、不获取外部网站、不调用 AI。

测试覆盖：权限、日期与分页校验、自然日边界、主库/归档覆盖优先级、空日期不回退、条目隔离、精确话题匹配与碰撞、1h/4h 采样与断档、未上榜、单点、排名轴、未来日期提前生成和空数据保护。随后运行完整测试、类型检查、lint、构建与临时库桌面/手机交互验证，并进行 code review。没有用户再次明确要求，不 push。
