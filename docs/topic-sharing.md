# 单话题双语分享与编辑推荐

本功能支持每日一套英文四图主帖，以及从所选日期和前一天挑出的 2–3 条单话题。
每条单话题同时生成英文、中文本地化文案与卡片，不会自动向 X 发布。

## 入口与制作

1. 管理后台 → 小时报 → 查看详情 →「生成单话题分享」。原始条目存在关联聚合话题时，使用该聚合话题的已保存分析。
2. 管理后台 → 日报 → 选择条目 →「生成单话题分享」。
3. 管理后台 → 分享制作 →「今天与昨天，哪些话题值得讲清楚」→ 从 English picks 或中文推荐选择。

打开编辑器只读取资料。先查看原始来源与材料限制，再选择栏目、点击「生成双语文案 · AI」。
任务在后台继续执行，编辑器轮询完成后载入保存稿；也可从任务日志重新打开。
显式生成先规划并执行有上限的补充查询，再用一次正文请求同时生成中英文主图、配文和配套文章。数字、翻译、评论依据及文风疑点只提示，不触发修正循环，也不会阻断保存稿。
缺少真实评论时，已有 AI 分析中的网友态度判断不作为评论原文证据；模型会明确收到中英文评论是否可用的标记。

三个栏目分别为：

| 栏目 | 中文名称 | 材料要求与编辑重点 |
|---|---|---|
| Inside China's Internet | 中文互联网观察 | 一个具体事件或文化现象，以及海外读者缺少的语境 |
| In Their Words | 他们怎么说 | 有来源、标签匹配、已有英文译文的真实评论；可以只有一个观点 |
| China Tech, in Context | 中国科技，放回语境 | 科技、汽车或消费发展，区分厂商主张、计划、演示与已确认结果 |

新稿每种语言各有三份主帖配文候选、主图标题、新闻简述、一句点评、配套文章标题与正文、补充回复和 ALT。主图不显示「为什么值得关注」「讨论问题」或长篇背景；文章负责展开事实、背景、后续进展和明确点评。旧稿保留原布局与编辑字段，重新生成后应用新格式。
英文补足陌生背景，中文从具体情境和实际影响切入；管理员选择理由允许中文。
保存前可独立编辑，语言切换保留两边的修改。未保存稿不能重新生成或导出，版本冲突时保留本地文字。
「重新载入保存稿」会同时核对当前来源；来源已清理时仍可读取冻结稿继续编辑、下载。
ALT 建议控制在 1000 个 Unicode 字符内。自动检查会提示数字、单位、日期、引语和人群表述等疑点，最终由管理员核对判断。

### 生成与人工核对

翻译、措辞、意译和证据对应疑点由管理员判断，自动检查只产生后台编辑提示，不阻断生成、保存或下载。
生成与字段提示共用建议长度和语言信息；正文请求最多 9,000 输出 token，同时返回两种语言的短主图和文章，原始文案直接保存为可编辑双语草稿，不再为了消除规则提示而额外调用 AI、删除数字或重写候选。

这一次指正文生成，之前有一次查询规划请求。显式生成近两天的单话题时，若有态度分析，还会按统一限额尝试补取评论；评论分类可额外调用一次模型并使用共享缓存。采集、分类失败不阻断正文生成。新增资料与评论只冻结进本份分享稿，不回写原日报或小时报，不让其原有分享版本失效。来源指纹同时保留补充前的基础版本；强制重新生成仍核对基础来源和稿件版本，失败或空结果不会删除仍匹配原帖与立场的已保存评论。历史材料只复用已有评论证据，避免把今天的评论冒充旧日评论。

### 主动查询与文章

查询最多三个方向，优先具体事件、原始公告、后续结果及必要的背景定义。总预算包括规划、搜索、正文和跳转：最多 12 次 HTTP 请求、9 次页面尝试、6 篇正文、60 秒；单次读取最多 8 秒、1 MB，冻结正文每篇最多 6,000 字符。搜索摘要不作为已读取正文，验证页、无关页面和付费墙不绕过。

可配置私有 `BRAVE_SEARCH_API_KEY` 使用 Brave 官方搜索 API；未配置时使用公开新闻 RSS 与百科搜索。免费来源可能缺失或无法访问，后台会展示实际读到的正文、URL、查询和失败提示；不会承诺每次都有完整材料。`WCCAT_TOPIC_RESEARCH_ENABLED=false` 可关闭主动查询。检索失败只产生后台提示，仍生成可编辑稿件；公开文案不应反复描述内部缺资料的问题。

主图建议 45–65 个英文单词或 100–160 个汉字，再加一句短点评。文章按证据展开人物、地点、时间线、概念、争议、实际监测及最新进展，并在段落旁标注 `[r-来源ID]`。文章中的指责须有依据，明确评论可以提出具体责任标准，不能凭一个结果断言存在失职。管理员可以分别修改两个版本；自动提示不代替人工判断。

后台黄色「编辑提示」显示涉及的语言、字段或候选及提示原因，覆盖数字/单位/日期、引号、评论证据、语言混用、篇幅和候选角度等。
修改时实时更新，保存及重载时由服务端从当前文案与冻结来源重新计算，不信任客户端或旧记录里的提示数组。
提示不要求确认、不禁用操作，也不会写入公开 PNG、配文、回复、ALT 或来源文本。

缺少语言字段时保留可编辑空白；原始中文评论缺少英文译文不会阻断正文生成，中文卡片仍可展示原话。
已保存英文译文中的中文专名保留展示并提示，由管理员核对。栏目建议只作参考，管理员可选择全部已知栏目。
长卡片在保持可读字号和完整文字的前提下自动增高，预览与 PNG 按实际画布高度处理。

无法读取的 API 响应、网络失败、越权生成来源字段、危险控制字符、原始来源或稿件版本冲突仍属于技术或数据完整性错误，会保留旧稿。
原始评论身份、原文、点赞、引用来源与指纹仍由冻结资料提供。程序提示不代表翻译或事实正确性结论。

回归与真实生成覆盖带评论的太空握手、念诗及无评论的东北洗浴；后台实测涵盖带提示保存/重载、缺译文补写、手机布局、长卡片 ZIP 导出及提示不进入公开物料。

## 下载

- 新版当前语言 PNG：1080 × 1080，长文案自动增高而不截断。旧稿仍沿用原 1800 / 2160 高度。
- 完整双语 ZIP：双语 PNG、主帖配文、补充回复、ALT、`article-en.md`、`article-zh.md`、`sources.txt`、`experiment-notes.txt`，以及准备成功后的文章链接与来源回复。
- 配文文件使用所选择、已编辑并保存的候选。原始评论、点赞和链接来自冻结资料，不能通过文案编辑改变。
- 新版真实评论放在文章页，主图保持简洁；缺评论不显示空区块。不会显示“采样于 …”时间行。导出前检查排版，较长内容会自动扩展画布，不会静默裁掉文字；确实无法渲染时会显示具体技术问题。
- 生成后仍应核对原文与解释，尤其是人名、传闻、玩梗、因果判断及“首次/最大”等比较性主张。自动校验不等于完整事实核查。

## 推荐如何工作

推荐不调用 AI，也不抓取 X。候选来自所选日期及前一天的已保存日报，以及各日最新小时榜的前 60 个聚合话题。
英语、中文分别根据证据完整度、科技实体、跨文化解释、创作者社区、生活关联与核实风险评分。
相同标题、稳定话题 ID 或原始内容链接会去重；不把搜索首页当作同一原帖。
在相近优先级下保留栏目差异；资料不足时可以少于三条。
分值是可检查的编辑排序规则，不是爆款概率，也不是实时 X 趋势。
“某话题正在某平台获得注意力”等本地默认摘要不算故事事实；仅有标题时会降低优先级并提示先补充核实。

六种候选实验来自有限公开案例：具体观察、真实原话、数字语境、证据对照、文化梗解释、事件跟进。
材料不支持某种方式时，使用背景解读或待核实问题。见 [研究与案例](x-editorial-patterns.md)。

## 中英文日报四图

ShareEn 首图按原榜顺序展示完整 Top10 英文短标题，以颜色和箭头标出精选条目；后三图逐条展开并显示栏目。
足够支持三条故事时共四图；资料少时减少详情图，不虚构补齐。详情材料不足的条目仍保留在总览榜单中；原日报少于十条时展示实际条数。
正文首句直接进入发现，品牌和来源说明放末尾。已保存的旧版 ShareEn 继续按原布局预览、编辑和导出；
已经生成的编辑版日报也会直接展示完整榜单，重新预览、下载即可，无需再次调用 AI。

英文与中文分别发布，每种语言使用自己的四张图片和配文。中文直接从同一日报的已保存材料生成配套视图，不增加 AI 请求；选题、顺序和配图与英文一致。后台「中英双语 · 多图」可切换预览，「下载中英双语 ZIP」同时下载两个独立发帖包。详见[每日中英文卡片包](daily-bilingual-cards.md)。

## 保存与版本

单话题稿存在主库 `topic_shares`，包含冻结来源和编辑稿，独立于原小时报/日报。
清理小时数据后，仍能通过任务记录中的保存稿 ID 打开和编辑；原始来源被清理后无法再基于该引用生成。
生成请求、排队任务和落盘均核对来源指纹，手工保存还核对稿件 revision；维护前的迟到写入会被拒绝。
本模块不会覆盖原日报，也不会在预览和下载时触发收费请求。

现有按月业务归档未包含 `topic_shares`；已制作素材请另存完整 ZIP，整库备份则会包含此表。


## 发布素材与来源入口

主帖配文、单链接来源回复、固定版本资料页及图片资料编号已接入单话题、小时报选取的话题和日报多图下载。详细操作、下载文件与版本行为见 [X 发布素材与公开资料页](publication-materials.md)。
