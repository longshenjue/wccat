# 管理员数据归档与清理

本功能不接外部存储，不按周/月自动删除。所有已有日报长期保留，小时明细由管理员按需处理。默认后台关闭；原来的任意表增删改接口在生产继续关闭。

## 1. 配置登录

更新到包含本功能的版本。在本机项目终端运行：

```bash
npm run admin:password
```

在提示下输入至少12个字符的管理员密码（输入隐藏）。命令输出两项配置，把值分别填入 Northflank WcCAT 服务的 **Runtime Environment / Secrets**：

```dotenv
WCCAT_ADMIN_PASSWORD_HASH=命令生成的散列
WCCAT_ADMIN_SESSION_SECRET=命令生成的随机密钥
```

不要把密码、散列或密钥提交到GitHub，不要把它们作为构建参数。新散列使用冒号分隔，可以直接放进本机 `.env.local`，也可以直接放进平台 Runtime 变量。更换任一配置都会使旧登录会话失效。

保存配置并重启整个 WcCAT 服务，让网页、worker 和维护命令加载同一版本。访问 `https://你的域名/admin`，输入刚才的密码。会话有效期8小时，可主动退出。未配置或配置不完整时生产页面返回404。

## 2. 首次启用空间回收

在后台查看“空间回收”状态。新创建的数据库已经支持增量回收；旧数据库需要一次初始化。建议在数据库较小时点击“初始化空间回收”，按提示输入确认文字。

也可通过受控Shell执行：

```bash
cd /app
npm run storage:prepare
```

初始化保留全部业务记录，但会暂时阻止 worker/网页的业务写入。旧库初始化需要额外磁盘空间；空间不足时任务拒绝执行，不删除源记录。不要等磁盘完全用满才处理。不能同时运行旧版不带写入协调的 worker。

不要直接删除 SQLite 的 `-wal`、`-shm`，也不要在连接仍打开时裸替换主数据库文件。

## 手动生成指定日期的日报

登录后，在“日报”Tab 的“手动生成日报”选择内容所属日期。页面显示统计窗口和实际可用采样数；例如选择 `2026-11-13`，汇总北京时间 `2026-11-13 02:00 → 2026-11-14 02:00` 的快照，自动任务在11月14日凌晨2点生成这份11月13日日报。默认最近一个已结束窗口的所属日，也允许选择未来日期按已有数据提前生成，尚未结束的窗口会明确标记。详见[历史查询与热度变化](admin-history-and-trends.md)。

点击“生成日报”或“重新生成并覆盖日报”。已有同日期日报会被覆盖，不再额外确认；操作会调用已配置的 AI。没有有效小时快照或话题时拒绝执行，原日报保留。主库与已注册完整归档的快照均可用于补生成；仅日报归档不包含小时明细，无法凭它重新生成。

在“任务日志”Tab 的“任务与下载”查看对应日报任务：可展开带时间的日志，了解 Top10 汇总、TOP1 分析来源、中文稿件、英文翻译及最终保存情况。日志同时输出到 Northflank 容器日志。关闭或刷新页面不影响任务，重新登录后仍能查看结果和日报链接。任务与归档、清理共用串行限制，当前任务结束后才能提交下一项；不提供生成过程中的强制取消。

“已生成 · 有警告”表示中文日报已保存，但英文未就绪或部分内容采用本地回退；请查看实际模型及日志。英文失败不会删除已生成的中文内容。旧英文不会沿用到新中文内容。

日志只对管理员可见，自动脱敏。单条日志最多 2 KiB、每任务最多 256 KiB，超限会显示截断提示；30 天以前或超出合计 20 MiB 的旧日志在后续写日志时回收。回收只移除任务日志，不删除日报、归档下载证明及任务结果。

## 3. 查看范围并下载

后台显示主库、WAL、临时下载文件、注册归档和持久卷可用容量。月份体积是内容估算，不是磁盘精确分摊。

选择月份，或填起止日期（北京时间，包含结束日当天），点击“生成范围预览”。

- **完整归档**：所选日期的小时快照、来源、话题、已生成分析、AI日志及日报。可以恢复小时历史。
- **仅日报**：所选日期内已生成的日报，包含日报已保存的分析、稿件与英文；不包含完整小时历史。

跨月范围会生成多个按月的 `.sqlite.gz` 文件。可隔三个月只下载第一个月，也可随时下载某个月的一部分。导出不修改原始记录，不重新抓取，不调用AI。

“生成下载归档”完成后点击各文件的“下载文件”。页面提供SHA-256，例如本机校验：

```bash
shasum -a 256 /你的下载目录/wccat-*.sqlite.gz
```

下载中断可以重试，不能仅凭服务器响应完成判断已安全保存。请保存全部文件并核对校验值后再确认清理。

## 4. 两种清理方式

**下载后清理：**在对应的完整归档卡片点击“已保存文件，清理对应小时数据”，勾选确认并输入“清理小时数据”。只有整组文件都完成下载、管理员明确确认、数据版本仍匹配时才执行。日报归档不能作为完整小时数据已备份的依据。

**直接只留日报：**在范围预览点击“保留日报，清理小时数据”。这表示主动放弃对应小时明细，不会为其自动创建备份。

两种方式均：
- 保留所有已有日报 payload，包括已生成英文和分析。
- 保护最近48小时和最新小时记录，实际可清理数量以预览为准。
- 显示没有已生成日报覆盖的日期；若确实要放弃这些小时记录，需额外勾选确认。
- 不会凭空补齐缺失日报、AI分析或英文。日报只保留当日已生成的内容，不是全部小时内容的替代品。
- 删除关联小时来源、话题、分析与日志后，回收 SQLite 空间。
- 在预览后有分析或稿件变化时拒绝旧确认，要求重新预览/导出，防止遗漏新内容。

任务独立运行，关闭页面不影响；回到后台可查看结果。清理和压缩开始后不能中断。若显示“小时清理已提交，但空间回收尚未完成”，记录已删、日报保留，请使用“回收空闲空间”重试，不要把它当成尚未删除再重复操作。

清理完成后会移除对应服务器临时下载文件；只下载不清理时，可点“移除临时下载文件”，不影响源业务数据。超过24小时的旧临时文件会在下一次导出时回收。暂停/失败任务留下的状态会显示失败，不自动重试删除。

## 5. 在另一台部署恢复

复制归档包到目标服务器的受控目录，使用**同版本或兼容版本**应用批量注册：

```bash
cd /app
npm run archives:register -- /受控目录/wccat-2026-09-....sqlite.gz /受控目录/wccat-2026-10-....sqlite.gz
# 也可以让 Shell 展开多个文件：
npm run archives:register -- /受控目录/wccat-*.sqlite.gz
```

命令会解压、检查 schema/数量/内容校验值和 SQLite 完整性，原子地注册到：

```text
/app/data/
├── wccat.sqlite          # 主库：新数据继续写在这里
└── archives/
    ├── registry.json    # 自动维护的索引
    └── <内容校验值>.sqlite
```

之后网站自动扫描注册索引，按日期读取对应归档。多个月份和同月多个部分归档可以共存，重复注册不会重复显示；同日期按业务生成时间取较新版本，时间相同优先主库。不会覆盖主库中新补生成的英文。

日报支持按月份导航。小时记录已经从当前部署清理且未恢复时，会明确显示“暂无小时记录”，不再把最新榜单当作历史记录。

只恢复日报包时只能查看日报；需要完整小时历史就必须保存并注册完整包。原封面仍依赖外部图片地址可用，归档不下载原图。

恢复前检查目标空间。注册期间只处理受控文件，不执行文件自带SQL脚本；不支持把未知版本的任意SQLite数据库当作归档。注册进程意外终止时，先确认该进程不再运行，再移除目标 `archives/registration.lock` 后重试；未完成的注册不会发布到索引。

## 6. 存储与迁移边界

- 持久卷继续挂载整个 `/app/data`，实例保持1个。
- 主库数据仍在 `wccat.sqlite`；临时导出位于 `admin-exports`，已注册只读历史位于 `archives`。
- 将归档留在当前卷上仍然占容量；想节省当前站空间，应下载保管并移除相应小时数据和临时文件。
- 清理只作用于选定的主库小时数据，不删除已注册的只读历史归档文件，也不删除日报。
- 没有自动向其他服务器同步；导出格式和注册命令用于迁移。持久卷不代替独立备份。
