## platform-tier-v3：平台分级决定上限，互动决定站内表现

此版取代未发布的 cross-platform-v2。保留真实互动，不直接跨平台比较播放、点赞、评论的绝对数；
也不再直接排除 B 站单平台内容，不设置平台入选配额。

### 每次采样的站内评分

比较池为同一平台、同一次采样的前 50 位不同标题。微博历史 rank=0 兼容为第一位；其他异常榜位不计分。
不同采集接口的同源同标题条目合成一个比较观察点；分数共享，原始证据保留。

```
平台贡献 = 档位上限 × 站内表现（0～1）
站内表现 = 可用部分的加权平均：榜位 60%、站内热度分位 10%、站内互动分位 30%
榜位表现 = max(0.05, 1 - (榜位 - 1) / 50)
```

热度和每种互动指标都只转换为本平台比较池内的中位秩分位 `(较低条目数 + 0.5 × 相同条目数) / 有数据条目数`。
同一平台所有互动数放大十万倍，也不会增加它跨平台的分数。
指标至少有 5 个不同条目提供数据、覆盖池内至少 60% 条目且存在数值差异时才参与；全零、常数、单条或稀疏字段不产生额外表现判断。

互动按三个组等权平均，每组内部再对可用指标等权：

- 传播：播放/浏览/阅读取最大值，防止别名重复。
- 反应：点赞/赞同取最大值，再与收藏、分享、反对互动的分位平均。反对票表示注意力，不表示支持。
- 讨论：评论/回复取最大值，再与弹幕的分位平均。弹幕只进入讨论组一次。

缺失、负数或非有限数都不作为零互动；缺少某项时，在可用部分重新分配权重。
没有可用互动时可以仅按榜位或榜位加热度竞争；不会为“字段多”增加总预算。
分位只描述已采集热榜内的相对表现，不是该平台全部内容的百分位，更不是全体网民态度比例。

### 小时榜与日报聚合

小时榜同一话题同一平台取最高贡献，不将多个帖子重复相加；不同平台贡献求和。
不再添加原来的类别分、官方共振额外分、跨平台幂次奖励或突破上限的互动奖励。
来源种类与共振标签仍可用于解释内容。

日报查看所有已保存聚合话题，不截小时 Top30，并用每次采样的完整原始证据池重算站内表现，忽略旧 platformScore、heatScore 和综合排名。
每四小时一个分块，同平台同话题同分块取最高表现；手动重复采样不增加持续分。

```
平台全天贡献 = 本档上限 × (70% × 日内最高表现 + 30% × 平均表现)
平均表现 = 话题各分块表现之和 / 该平台实际有有效热榜数据的分块数
日报分 = 各独立平台全天贡献之和，最后四舍五入
```

平台采集缺失的分块是未知，不当成该话题无人关注；平台成功采到但没有该话题的分块则计为未观察到在榜。
无论帖子数、采样次数、互动绝对数多大，B 站在一条话题上全天最多 400 分，抖音最多 300 分，知乎最多 500 分。
同一话题在 B 站和抖音出现，平台贡献合计最多 700 分。平台越多可自然累加，不保证任何平台的入选名额。

新日报的 `rankingEvidence` 记录规则版本、独立平台、各平台档位、上限、最高/平均表现、有效/在榜分块数及贡献，方便逐项审查。
来源链接每平台优先一个，避免同平台多链接看起来像多个平台。

### 同一新闻进展去重

小时榜和日报共用 `news-facts` 的保守判定，不再用宽泛的字符相似度决定合并。
日报先读取所有保存的来源标题重新分组，再重算平台贡献和选择 Top10；去重腾出的名额从完整候选池补足，有效候选不足十条时不编造内容。

- 合并明确的等价写法：中文/阿拉伯任务编号（含“神24”）、同一发射成功的冗余措辞、“某地就某事表态／某事 某地表态”，以及仅交换完整分句顺序的标题。
- 地方机构“等表态”的集合式标题可与同一地点的概括标题对应；明确指名的两个不同单一机构不会通过一个概括标题间接合并。
- 保留动作、结果、问句、否定、日期、关键数量及主体关系。任务编号保留“号”边界，避免任务号与后面的日期拼接；回应标题尊重逗号、空格划分的主体，两个无明确分句的推测拆分不能相互证实。被查、表态、再次表态、免职，以及发射、对接等不同进展分别竞争；只出现相同人名、地点、任务或同一时段不能触发合并。
- 每个组的全部不同标题须两两兼容，防止 A 像 B、B 像 C 就把 A/C 强行合并。无法证明等价的同义改写暂时保留，规则不承诺识别所有语义重复。
- 旧小时快照中误混的进展按原始来源标题拆分；旧分析和摘要必须与最终组的全部标题兼容才可复用，并优先选取已保存的有效 AI 分析，避免因另一个标题旧分较高丢掉可用结果。拆分后的峰值分、峰值榜位与升降信号按当前规则重建每次采样榜单，情绪只根据本组标题重新推断，不继承混合父组。来源 URL、平台榜位与原始快照不被改写；新话题采用有长度上限的 ID，站内比较键保留事件阶段，避免旧规范化删除“回应”等词造成碰撞。

合并不是把两条旧日报分相加：仍然按“同平台、同四小时分块取最高表现”统一重算，上限和平台档位不变。
同一采样出现几个标题变体也只记一次采样。去重不新增采集或 AI 请求。

2026-11-25 案例用该日报六次公开保存采样（5,026 条来源记录）离线回放：原 Top10 中三个表态标题合为一组、两个发射成功标题合为一组，重新排序后仍为十条；同一航天事件中的其他具体动作保持独立。
这些标题仅用于聚合算法验证，不是对其事实真实性的核实。既有日报和中英分享图需在管理员中**重新生成日报**，再下载更新后的整套物料；只重新下载旧图不会重新聚合。

## 历史数据与验证

### 日报按新闻主线组织，具体进展仍然保留

2026-11-26 的三个蔡磊相关条目分别描述见面片段、病情报道和本人回应。它们不必是完全等价的事实，但不适合占据综合日报的三个位置、再占满三张详情卡。因此增加独立于事实去重的 `story-diversity-v1` 编辑层：

- 从完整的事实候选池计算分数，先不截 Top10。一次 AI 请求最多查看前 40 个候选的 ID、标题与短摘要，最多输出 2,200 tokens，30 秒超时，不自动重试，不新增抓取。
- 只把同一具体新闻主线的报道、回应、反应和紧密后续归为一条。共同人物、公司、地区、主题或日期本身不足以归组；原有小时榜与事实判重规则保持独立。
- 每条主线使用得分最高的现有事实作为主条目；保留该事实原分数和评分证据，不把不同进展分数加在一起。其余事实保存在 `relatedDevelopments`，携带各自标题、分析、分数和来源。空出的名额从完整候选池依次补足，最多十条。
- 日报可展开其他进展；英文生成、中文资料、单话题分享及公开来源页沿用同一组材料。中英文卡片使用相同主条目 ID；原来三条同一主线的子进展不会分别竞争三张详情。主条目没有正文而后续进展有正文时，使用明确标注进展标题的证据；不借用其他进展的红蓝态度或评论。仅有标题或排名模板仍不算事实背景。
- 归组最多包含八个事实，每个事实最多六个原始平台链接。单话题冻结来源保留这 48 个链接的上限；评论抓取的线程数、每线程条数与每日预算保持原设置。
- 模型未配置、请求失败或返回非法/未知/重叠 ID 时保留普通排名，在日志和 admin 分享页提示人工检查，不阻断生成、保存和下载。前 40 条之外没有进行语义归组，补位时仍可能遇到未识别的相关主线；这是一层可审阅的编辑判断，不是对所有语义重复或新闻真实性的保证。

旧日报及已经公开的资料页不被自动改写。要应用这次选题规则，需**重新生成日报**，而不是只重新生成英文分享或重新下载旧图。普通预览、阅读和下载不会为此调用分类模型。

旧日报保持原样，管理员重新生成时才使用新排序，并重新生成对应稿件与分享物料。只下载旧图不会更新排序。
没有有效榜位候选时停止付费生成并保留已有日报；只有一个平台成功采集时仍可按真实证据生成，并在来源覆盖日志中显示缺失情况。
本次不增加抓取请求，也不要求全量评论；使用已有快照中的指标即可。

回放使用上述同一八次采样：原日报 Top10 中七条为 B 站单平台、零条包含抖音。当前配置回放仍有十条，B 站单平台零条、三条包含抖音、零条包含知乎；提高档位不保证平台入选，不构成未来平台配额。
分档是初始版本，后续应结合更多正常日与数据缺失日回放校准，不能仅为了让某个日期出现预期结果调参。
